# 能力测试报告：DeepSeek V4.1 Flash 单次任务全流程

本仓库是一次**模型能力测试**的产物：把一条中文需求整段交给模型，由它独立完成"设计 → 建模 → 动画 → 光照 → 交互 → 自测 → 交付"的全过程。此文件记录需求、验证手段、逐轮发现并修掉的缺陷，以及最终自评。

---

## 1. 测试题目（原文照录）

> 使用 Three.js 创建一个精致、可交互的 3D 网页场景：一只鹈鹕正在骑自行车。
> 鹈鹕、自行车、环境、动画、灯光、摄像机和交互均通过程序实现。
> 鹈鹕需要真实地骑自行车，并具有协调的腿部、脚踏、车轮和身体运动。
> 不要使用 SVG、2D Canvas、外部 3D 模型或预渲染动画。
> 最终输出一个可以直接在现代浏览器中运行的完整 HTML 文件。

**显式约束**：Three.js；全程序化；四类素材禁用；四者运动必须协调；单文件可直接运行。

**隐含要求**：中文语境下的"精致"意味着不能只是能跑，还要好看、有细节、有质感。

## 3. 验证手段

模型看不到画面。为了不"盲写"，先搭了一条可视化闭环：

1. **无头 Chrome + SwiftShader** 渲染页面并截图（`--headless=new --enable-unsafe-swiftshader`），确认 WebGL 可用；
2. 页面内置一次性 URL 参数：`adv`（定步长快进 N 秒）、`freeze`（冻结）、`view`、`cam=方位角,仰角,距离,注视高度,FOV`、`tod`、`speed`、`honk`、`nohud`——**让"某一瞬间的某一角度"完全可复现**；
3. 截图回读检查，多相位用 `tools/contact_sheet.py` 拼成对比图；
4. 语法先用 `node --check` 卡一道，再用 `--dump-dom` 读取 DOM 判断页面是否真的初始化成功（加载遮罩是否撤掉、HUD 是否更新、错误提示层是否出现）。

总迭代量：**约 20 轮渲染-回读循环**，每轮都看图改代码。

## 4. 逐轮发现并修复的缺陷

| # | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | 画面里一个巨大惨白圆盘压在地上 | 太阳圆盘建好后忘了更新位置，一直停在原点 | 每帧置于 `相机位置 + sunDir × 640`；日落后自动翻到对侧变月亮 |
| 2 | 翅膀上炸出一排黑色尖刺 | 骨骼坐标系里"后方"参考向量在骨向与后方共线时投影退化，且羽片旋转方向写反 | 改用解剖学拖曳方向 `(0,-0.72,-0.69)` 做投影；羽片朝向按"沿骨 + 垂坠"重新标定 |
| 3 | 肩部覆羽像豪猪刺 | 覆羽长度 0.24 ≈ 上臂长度，等于又长出一对翅膀 | 缩短到 0.135，紧贴臂面 |
| 4 | 喉囊几乎看不见、上喙尖端像香蕉 | 喉囊下垂量 0.14 偏小；尖端上翘项 0.115 过大 | 喉囊下垂加到 0.185、加宽到 0.098；上翘降到 0.030 |
| 5 | 头像鹅不像鹈鹕 | 脖颈过长过粗、头偏小 | 缩短并压低颈曲线，头半径 0.135 → 0.158，压低重心成"骑行驼背"姿态 |
| 6 | 肘部外翻像企鹅鳍 | IK 极向量指向外侧上方 | 改为向后下方收（`(±0.62, -0.50, -0.58)`） |
| 7 | 夜里几乎全黑、天上没月亮 | 夜间光强过低 | 月光 0.22 → 0.55、半球光 0.30 → 0.62、加月亮（尺寸 0.55×、淡蓝） |
| 8 | 屏幕顶部一条生硬白板 | 云太近太大 | 距离 40–130 → 150–280，高度 30–48 → 58–98 |
| 9 | 路面两侧泥土带过宽 | 路肩混合区间 2.2–4.6 m | 收窄到 1.85–3.35 m |
| 10 | 加载遮罩永不消失、HUD 全为 0（截图全黑） | 把"撤遮罩 + 刷 HUD"一起放进了 `累计时间 > 0.35s` 的分支；无头虚拟时间下该条件始终不成立 | 首帧必定执行一次，之后按 0.35 s 节流 |
| 11 | 翅羽遮住蹬踏的腿，看不清协调性 | 次级飞羽长 0.245 且近乎垂直下垂 | 缩短到 0.17 并让羽片更贴臂，把腿部动作让出来 |

第 10 条最典型：**代码逻辑本身没错，错在它把"用户能看到什么"交给了时间累积**——真实浏览器里 0.35 秒就过去了，但任何"帧时间不前进"的环境都会永远卡在加载页。这类缺陷只有真的去截图才能发现，读代码是读不出来的。

## 6. 已知不足（诚实清单）

- 鹈鹕的体表仍是光滑曲面 + 覆羽片，没有做真正的羽毛位移/法线细节，近看偏"玩具感"。
- 骑手沿固定闭合样条行驶，变线只是路面内偏移，不是自由操控。
- 车轮、曲柄、腿部是纯运动学联动，没有物理引擎，不会打滑或摔倒。
- 云与雁群是低多边形色块，没有体积感。
- 首次加载依赖 CDN（已给 3 个备用源与失败提示，但离线仍不可用）。
- 帧率数字来自软件渲染环境，不代表真机表现。

## 7. 结论

在**零人工介入代码编写**的前提下，模型自主完成了：几何方案设计（自写参数曲面而非拼积木）、运动学建模（IK + 齿轮比 + 侧倾公式）、工程自测闭环（无头截图 + 可复现参数 + 相位对比），并在此过程中定位修复了 11 个缺陷——其中第 1、2、10 条如果不看图是绝对发现不了的。

单文件 80 KB，约 1780 行，纯手写 JavaScript 与 GLSL-free 着色方案，无任何第三方几何库（连 `BufferGeometryUtils` 都没引入，合并几何是自己写的）。
